What is a skill?

  • A markdown file with a YAML header
  • Lives in .claude/skills/ (project or global)
  • Invoked explicitly /skill-name or automatically by context
  • There's a skill for creating skills
Keep this TIGHT — 5 minutes max. They just need the mental model. Show the .claude/skills/ directory in the file tree. Best Practices

  • The interview pattern — teach the skill to ask questions first
  • Start vague, refine through use — don't write the perfect skill upfront
  • Marketplace for gaps — use pre-built skills when you lack domain expertise
  • Custom for your expertise — your knowledge + iteration beats any template

You don't need 100 skills. You need 3–5 that are really dialed in.

BEST PRACTICES: 1. THE INTERVIEW PATTERN: "A good skill knows what it doesn't know." Teach skills to ask questions before making assumptions. Every competitor is different. 2. START VAGUE: Don't try to write the perfect skill upfront. Build, use, get feedback, iterate. 3. SKILLS ECOSYSTEM: • Marketplace skills: when you LACK domain expertise (UX accessibility, legal compliance). Someone who knows encoded the right questions. • Custom skills: when you HAVE domain expertise. Your knowledge + iteration > generic template. • Middle path: download a skill, read it (it's just markdown), delete what doesn't apply, customize the rest. 4. QUICK SHOWCASE: • Humanizer — turns AI slop into natural writing. "What if we made it sound like YOU?" • Brainstorming — structured creative exploration before building • Mention Vercel's skill repository DOMAIN EXPERTISE PRINCIPLE: "The best skill builders aren't the most technical — they're the ones who know their domain best."
